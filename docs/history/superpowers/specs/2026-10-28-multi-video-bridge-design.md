# Multiple video sessions in one ordinary-Chrome bridge

Approved by owner in conversation, 2026-10-28. Fix the one-scope/one-job reuse failure without cancelling existing work. Keep ordinary Chrome background delivery and existing media providers. Do not implement true concurrent video execution yet; track it in root TODO.md.

A bridge is the connection to its owner Studio tab, while each newly submitted video gets its own child connector scope and immutable exchanges. Existing root scopes/jobs/smokes remain readable and recoverable. One fresh root heartbeat plus its accepted smoke authorizes its child scopes; it does not authorize unrelated bridges. Replaying a job's idempotency key returns the same job/scope. New allocations and membership must be atomic; no reused old scope or orphan job after rejection.

New child allocations require a fresh active `videostudio-extension-0.3.0` heartbeat, because the old root-only poller cannot discover children. Old receipts remain readable; the existing root smoke may be reused after the owner reloads the new extension. Do not forge a new heartbeat or test response on behalf of the user during deployment.

API contract (root is the connected page's original connector scope):

- GET `/api/connector/bridges/{bridge}/sessions`: `{items:[{scope,job_id,title,project,state,stage,error,cancel_requested,created}]}`; include the legacy root-bound job plus children, exclude unrelated bridges. A root smoke with no job need not appear as a video card.
- GET `/api/connector/bridges/{bridge}/pending`: `{items:[{scope,job_id,is_smoke,id,version,prompt,attachments:[]}]}`; only scopes with active jobs (`queued`, `running`, `retrying`) plus the root smoke. `is_smoke` is server-attested using connector_smokes, and connection smoke has `job_id:null` even when its root has a historical terminal video. Failed/completed/cancelled jobs cannot block newer jobs. Keep receipt endpoints under existing `/api/v1/projects/{scope}/runs/{scope}/chatgpt-exchanges`.
- POST `/api/connector/bridges/{bridge}/jobs/{job_id}/cancel`: exact bridge ownership + existing same-origin protections, request cancellation for that job only, return scoped updated job summary. Existing API job submission header X-Connector-Scope continues to carry the bridge root; backend creates a new child per new extension job. Legacy non-extension transports keep their contract.
- Existing preflight and health keep the transport field. `accepted_extension(child)` uses its parent's current heartbeat/smoke. The parent can continue accepting new children when its legacy job failed/completed.

Extension keeps one owner bridge and a persisted slot per video scope (including a migrated legacy root slot), each with independent pending request, attempt budget, tab ownership and response. Snapshot returns legacy `job` alias plus `sessions:[{scope,job,...}]`. Studio messages specify scope; ChatGPT callbacks locate exactly one slot by request+tab+attempt. Claims for child scopes must be validated against the server's bridge session listing. Opening a new session never archives other slots. Stop pauses all; per-video cancel closes only that video's owned tabs and preserves receipts. Open Chat is an explicit user action and may activate only that session's owned tab. Automatic delivery/retry stays `active:false`.
